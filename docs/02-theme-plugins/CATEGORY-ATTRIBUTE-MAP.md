# Category + Attribute Map (Launch)

## Goal
Lock a simple, consistent structure for bracelet products to avoid later rework.

---

## Launch Categories
- **Bracelets**

(Planned later: Necklaces, Rings, Raw Stones, Tumbles, Gift Sets, Accessories)

---

## Attribute Strategy
Use a small set of **global attributes** that help filtering/search and keep naming consistent.

### Global Attributes (Launch)
1. **Stone Type**
   - Examples: Amethyst, Rose Quartz, Citrine, Tiger Eye, ...
2. **Wrist Size**
   - Examples: 14cm, 15cm, 16cm, 17cm, 18cm
3. **Bead Size**
   - Examples: 6mm, 8mm, 10mm
4. **Color**
   - Examples: Purple, Pink, Yellow, Black, White, Green, ...
5. **Material**
   - Examples: Natural Stone, Metal, Rope, Elastic, ...
6. **Intention**
   - Examples: Calm, Love, Protection, Energy, Focus, ...
7. **Zodiac** (optional at launch)
   - Examples: Aries, Taurus, Gemini, ...
8. **Birth Month** (optional at launch)
   - Examples: Farvardin... / Jan... (TBD based on target market)

---

## Variation Policy (Very Important)
Default: **Simple Product**.

Use **Variable Product** only if:
- size changes price/stock OR
- bead size changes the real physical product OR
- material changes the real product

If size is only “selectable preference” but you make the bracelet manually anyway:
- consider Simple Product + put size in product options workflow later
- or handle with 1 variation only when operationally needed

---

## Tag Policy
Tags are for soft discovery only.
Avoid using tags to replace attributes.

---

## Naming Rules
- attributes should be singular nouns (Stone Type, Wrist Size)
- use consistent capitalization
- avoid duplicates (e.g., "Stone" and "Stone Type" both existing)

---

## Exit Criteria
This document is complete when:
- attributes are approved
- variation policy is confirmed
- we can start entering the first 2 test products without changing structure
